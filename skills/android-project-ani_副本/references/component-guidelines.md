# 组件设计指南

## 按钮设计

### 按钮层级
- **主要按钮**：最突出，每屏最多1-2个，用于核心操作
- **次要按钮**：较低调，用于辅助操作
- **文字按钮**：最低调，用于取消、返回等操作
- **危险按钮**：红色系，用于删除、退出等破坏性操作

### 按钮状态
- **默认**：正常显示状态
- **悬停**：鼠标移入时（桌面端）
- **按下**：点击瞬间
- **禁用**：不可操作时，降低透明度或灰显
- **加载**：操作进行中，显示加载指示器

### 可点击性识别
- 保留矩形形状，最好带有圆角
- 扁平设计中也要保持可点击性视觉线索
- 不要让非可点击元素看起来像按钮
- 避免页面上有太多彩色方块相互竞争

### 按钮尺寸
- **大按钮**：高度 48-56px，用于主要操作
- **中按钮**：高度 36-44px，标准尺寸
- **小按钮**：高度 28-32px，用于紧凑场景

## 卡片设计

### 适用场景
- 浏览而非搜索的场景
- 异构内容集合
- 内容类型多样
- 需要视觉分组

### 不适用场景
- 用户需要比较多个选项时
- 展示高度同质化内容时
- 纯图片相册

### 设计要点
- 使用边框或背景色区分
- 轻微阴影表示深度和可点击性
- 点击卡片任意位置都可跳转（如果是可点击卡片）
- 允许不同高度适应内容
- 内边距保持一致

### 卡片内容结构
```
┌─────────────────────────┐
│  [图片/媒体区域]         │
├─────────────────────────┤
│  标题                    │
│  描述文字...             │
│  [标签] [标签]           │
├─────────────────────────┤
│  [操作按钮]    [更多 ▼]  │
└─────────────────────────┘
```

## 表单设计

### 核心原则
- 保持简短，删除不必要字段
- 视觉分组相关元素
- 单列布局（移动端必须，桌面端推荐）
- 逻辑顺序排列
- 避免占位符文本作为标签
- 字段大小匹配预期输入
- 区分必填和可选字段
- 说明输入格式要求
- 避免重置按钮
- 提供高度可见的错误信息

### 输入框样式变体
- **边框型**：四周边框，最常见
- **下划线型**：仅底部边框，Material Design 风格
- **填充型**：背景色填充，无边框或轻边框

### 标签位置
- **顶部标签**：最推荐，扫描效率高
- **左侧标签**：适合桌面端宽表单
- **浮动标签**：节省空间，但可能影响可访问性

### 错误状态
- 边框变红
- 显示错误图标
- 错误信息紧邻输入框下方
- 错误信息使用红色文字

## 列表设计

### 信息优先级
- 确定用户决策的关键信息
- 高优先级信息放在顶部和左侧
- 价格几乎总是关键信息

### 视觉层次
- 字体处理：增大字号、加粗或使用深色
- 留白隔离：用周围空白突出重要属性

### 跨条目一致性
- 相同属性在不同条目中位置一致
- 视觉处理方式保持统一
- 特殊状态标识不超过2-3种

### 列表项结构
```
┌─────────────────────────────────────┐
│ [头像]  主标题              [时间]  │
│         副标题/描述                 │
│         [标签]  [状态]      [操作]  │
└─────────────────────────────────────┘
```

## 导航设计

### 核心目标
- **可发现性**：用户能找到他们认为应该有的内容
- **可探索性**：用户能发现之前不知道的内容

### 常见问题
- 分类名称用户不理解
- 导航链接位置不显眼
- 导航组件被误认为广告

### 导航类型
- **顶部导航栏**：适合少量主要入口
- **侧边导航**：适合多层级、多入口
- **底部标签栏**：移动端主导航
- **汉堡菜单**：节省空间，但降低可发现性

### 当前位置指示
- 高亮当前页面对应的导航项
- 使用面包屑显示层级路径
- 页面标题与导航项名称一致

## 标签页设计

### 适用场景
- 长内容有明确分组
- 分组数量较少（2-7个）
- 内容重要性不均等
- 内容可简洁命名

### 设计要点
- 明确指示选中状态（至少两种指示器：颜色+下划线/背景）
- 保持未选中标签可见可读
- 连接标签与面板（视觉上相邻）
- 只使用单行标签
- 标签列表置于面板上方

### 标签页样式
```
选中态：
┌─────────┐
│  标签A  │  标签B    标签C
└─────────┴─────────────────────

或：

  标签A    [标签B]   标签C
  ─────────────────────────
```

## 模态框/弹窗设计

### 适用场景
- 重要警告和防止严重错误
- 请求继续流程所必需的信息
- 将复杂工作流分解为简单步骤

### 不适用场景
- 非必要且与当前流程无关的信息
- 高风险流程中（如结账）打断用户
- 需要额外信息源的复杂决策

### 设计要点
- 标题清晰说明目的
- 内容简洁，避免滚动
- 操作按钮明确（确认/取消）
- 提供关闭方式（X按钮、点击遮罩、ESC键）
- 遮罩层降低背景干扰

### 模态框结构
```
┌─────────────────────────────┐
│  标题                    ✕  │
├─────────────────────────────┤
│                             │
│  内容区域                   │
│                             │
├─────────────────────────────┤
│           [取消]  [确认]    │
└─────────────────────────────┘
```

## 空状态设计

### 三个核心原则
1. **传达系统状态**：避免完全空白，告诉用户发生了什么
2. **提供学习线索**：告诉用户可以做什么
3. **提供直接路径**：给出关键任务的快捷入口

### 空状态类型
- **首次使用**：引导用户开始
- **无搜索结果**：建议调整搜索条件
- **无数据**：说明原因，提供创建入口
- **错误状态**：说明问题，提供解决方案

## 搜索框设计

### 核心原则
- 使用输入框而非链接
- 位置要显眼（通常在顶部）
- 宽度要足够容纳典型查询
- 每个页面都应可用
- 优化短查询处理

### 增强功能
- 搜索建议/自动补全
- 最近搜索历史
- 热门搜索推荐
- 搜索范围筛选

## 加载状态设计

### 选择指南
- **< 1秒**：无需任何指示器
- **1-3秒**：简单加载动画（spinner）
- **3-10秒**：骨架屏或进度指示
- **> 10秒**：进度条 + 预估时间

### 骨架屏设计
- 使用浅灰色方块代表内容
- 结构模拟最终页面布局
- 可添加脉动动画
- 不要使用仅显示框架的骨架屏

### 加载动画位置
- 全屏加载：居中显示
- 局部加载：在加载区域内显示
- 按钮加载：在按钮内显示
