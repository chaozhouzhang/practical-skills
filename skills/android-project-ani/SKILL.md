# android 动物喂养规划 App 搭建工具

## 核心目标
从零搭建一个可运行的 Android 动物喂养规划 App，使用 Kotlin/Compose 实现基础功能与视觉风格体系。用户可指定动物/喂养对象与 App 风格，输出应包含完整 Kotlin 代码与清晰的文件结构。

## 输入与可选项
用户可能提供以下信息：
- **动物/喂养对象**：例如“猫”“狗”“兔子”“鹦鹉”“爬宠”“观赏鱼”等，可为单个或多个
- **风格**：例如“极简”“清新”“日系”“科技感”“治愈”等
- **可选功能**：喂养计划、提醒、喂养记录、日历计划、体重/健康记录、喂养统计等

若信息不完整，应主动询问补充；若用户不确定，可给出默认建议并让用户确认。

## 能力边界
**必须做到**
- 使用 Kotlin/Compose 编写核心代码
- 从 0 搭建项目结构（App 入口、数据模型、视图层、主题样式）
- 根据指定动物生成默认数据与文案
- 根据指定风格生成统一的视觉主题（颜色、字体、形状、间距）
- UI 展示文本不要使用中文，默认使用英文（除非用户明确要求其他语言）

**不要做**
- 引入第三方依赖（除非用户明确要求）
- 引入后端、网络请求或复杂同步（除非用户明确要求）
- 加入通知、相机或系统权限（除非用户明确要求）
- 使用WebView

## 工作流程

### 第一步：需求确认
至少确认三类要素：
1) 动物/喂养对象（单个或多个）
2) 风格/气质（关键字即可）
3) 需要的功能范围（基础/增强）

当用户只提供模糊描述时，给出 2-3 个可选方向让用户选择。

### 第二步：确定功能范围
默认基础功能（若用户未指定）：
- 动物列表（AnimalList）
- 动物详情（AnimalDetail）
- 添加/编辑动物（AddEditAnimal）
- 喂养计划（FeedingPlan）
- 喂养记录（FeedingLog，可选）

如用户指定增强功能，再补充：
- 日历视图
- 体重/健康记录卡片
- 喂养统计与目标达成

### 第三步：建立数据模型
建议最小模型：
- `Animal`：名称、物种/品种、头像、年龄、体重、状态、标签、备注
- `FeedingPlan`：目标类型（每日/每周/固定次数）、起止日期、喂养时间（仅应用内展示）、食物类型、份量
- `FeedingLog`：日期、食物、份量、备注

若用户指定动物清单，模型中的默认数据应体现该清单（名称、品种、头像占位图名、默认计划/记录），但不做医疗建议，仅作为占位内容并允许用户调整。

### 第四步：构建主题系统
根据用户风格生成统一主题：
- 颜色：主色/辅色/背景/文字/状态色
- 字体：标题/正文/说明层级
- 形状：圆角、边框、阴影策略
- 间距：基础间距与层级

实现方式：建立 `Theme` 或 `DesignSystem`，并在组件中统一使用。

### 第五步：搭建 Compose 结构
建议基础结构：
- `App` 入口 + `RootView`
- `HomeView`（汇总）
- `AnimalListView` / `AnimalDetailView`
- `AddEditAnimalView`
- `FeedingPlanView`
- `FeedingLogView`
- `SettingsView`（可选）

组件要遵循统一的主题系统，不要出现风格杂乱。

### 第六步：输出与说明
输出内容包括：
- 生成/修改的文件清单
- 每个文件的职责说明
- 风格与动物清单如何体现在 UI 与数据中
- 后续可扩展点（若用户询问）

## 质量检查
- 主题一致性：颜色、字体、间距、形状是否统一
- 数据自洽：动物信息、计划、记录、文案是否一致
- 功能完整：动物列表、详情、添加、计划、记录是否可用
- 代码清晰：结构清楚、命名一致、无多余复杂度
- 换行检查：例如navigation的tab的名称、按钮的名称、标签的名称，不要有换行问题
